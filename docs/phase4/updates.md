# 自動更新の確認（Phase 4）

コード: `crates/blongo-client/src/update.rs`、`crates/blongo-client/src/http.rs`、設定画面の Updates。

**ダウンロードまでで、インストールはしません。** 本物の更新サーバーはまだ無く、テストはループバックの偽サーバーだけで行っています。

## マニフェスト

更新サーバーは次の JSON（エンベロープ）を返します。

```json
{ "manifest": "<base64: マニフェスト JSON のバイト列>", "signature": "<base64: そのバイト列への ed25519 署名>" }
```

マニフェストの中身:

```json
{ "version": "0.2.0", "url": "https://…/blongo-0.2.0-linux-x86_64.tar.gz", "sha256": "<64桁の16進>", "notes": "…" }
```

- 署名は、ビルドに埋め込んだ公開鍵（`update::RELEASE_KEY`）で確かめます。署名が合わないマニフェストは中身を一切信じません（バージョンの比較もしない）。
- 署名済みのマニフェストのバージョンが今のバージョンより新しければ「更新あり」。比較は数字ごと（`0.10.0` > `0.9.9`）、プレリリース（`-rc1`）は同じ数字の正式版より古い扱い。
- ダウンロードは `<data_dir>/updates/`（0700）に保存し、SHA-256 がマニフェストと違えば削除してエラーにします。最大 512 MiB。
- URL は https のみ（テスト用にループバックの http だけ許可）。

## 設定

- リリースビルドでは `RELEASE_KEY` と更新 URL を埋め込む想定です（今は `None` = 更新の確認は無効）。
- 開発・テスト用に `BLONGO_UPDATE_URL` と `BLONGO_UPDATE_KEY`（公開鍵の base64）で指定できます。
- 設定画面の「Check now」で確認、「Download」でダウンロード。「Check at start」を入れると起動時に確認し、更新があれば通知欄に出します。

## 残り

- インストール（アーカイブの展開、実行中バイナリの置き換え、再起動）。OS ごとに作法が違い、macOS は署名・公証、Windows はインストーラが絡むため、配布の仕組みと一緒に作る。
- 鍵のローテーション（複数の公開鍵を受け付ける）。
